## 1. 접수 (Scope 8.1)

### QA-001 [정상] 접수 생성 — 정상 흐름
- **사전조건**: API 구현 후 실행 가능 (현재 미구현)
- **입력**: 사업소(OFFICE-001), 수거 희망일(오늘+1일), 장소 유형(사업소), 주소("광주광역시 OO로 OO"), 전동침대 1, 휠체어 0, 기타 0
- **절차**:
  1. FastAPI 서버 기동 (`uv run app/server.py`)
  2. POST /api/requests 엔드포인트 호출
  3. 응답 확인
  4. DB에서 해당 접수 건 조회
- **기대 결과**:
  - 접수번호 부여됨
  - 현재 상태 `RECEIVED`(접수)
  - 생성 시각 기록됨
  - DB에 1건 저장됨
- **증거 위치**: DB 조회 결과(`runtime/db/ju-project.db`), 로그
- **실행 방식**: API 호출 + DB 검증

## 12. 위험

1. **SQLite 동시 쓰기 경합** — 단일 파일에 대한 쓰기 잠금으로 인해 동시 카운터 증가 시 `OperationalError: database is locked` 발생 가능. 1단계는 단일 프로세스이므로 실무 영향은 작으나, 향후 멀티프로세스 확장 시 재설계 필요. (데이터-모델 10절)
2. **Alembic `downgrade` 안전성** — `DROP TABLE`은 개발 단계에서만 사용해야 하며, 프로덕션에서는 `downgrade` 실행 시 데이터 손실 발생. 리비전 체인 순서 오류 시 `alembic upgrade head`로만 진행해야 함. (데이터-모델 10절)
3. **UTCDateTime TypeDecorator 테스트 커버리지** — DB 저장/조회 변환 로직이 단위 테스트로 검증되지 않으면 naive datetime 혼재 위험. `process_bind_param`과 `process_result_value` 모두 테스트 커버 필요. (데이터-모델 10절)
4. **Enum `native_enum=False` 길이 제한** — `length=20`이 `RequestStatus` 값들의 최대 길이보다 충분히 큰지 확인 필요. 값 변경 시 `length` 재설정 불가 — SQLite는 ALTER COLUMN 길이 변경을 지원하지 않음. (데이터-모델 10절)
