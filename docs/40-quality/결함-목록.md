## 1. 확인된 결함 (기능·보안·데이터 무결성)

### 1.1 [중간] 500 응답에 내부 예외 메시지 노출
- 위치: app/main/api/requests.py 97-101
  (`except Exception as e: ... detail=f"상태 변경 실패: {str(e)}"`)
- 내용: 상태 변경 중 예기치 못한 예외 발생 시 예외 본문 전체를
  HTTP 500 응답 detail에 포함해 반환한다. DB 경로·스키마 등
  내부 정보가 응답에 노출될 수 있는 구조다.
- 재현 절차:
  1. 상태 전이 API에 예외를 강제(예: DB 파일을 삭제/잠금 후
     `PATCH /api/requests/{id}/status`)
  2. 500 응답 detail에 예외 메시지 원문이 담김
- 기대: 500 응답은 클라이언트 안전 메시지 + 서버 로그에 상세만 기록
- 실제: `detail=f"상태 변경 실패: {str(e)}"`
- 심각도: 중간 (로컬 1단계 프로토타입, 인증 없음이므로 노출 범위 제한적)
- 차단 여부: 출시 차단 조건에 해당하지 않음(권한 우회/개인정보 노출 아님)

> 본 청크에서 발견한 출시 차단 조건(인증/권한 우회, 개인정보·자격증명 노출,
> 상태·알림 중복·누락, PDF 타 거래처 노출, 엑셀-DB 불일치, 복구 불가 데이터

## 2. 미검증 위험 (결함 아님, 관리 대상)

아래는 현재 테스트로 검증되지 않았거나 검증이 불가한 항목이다.

### 2.1 SQLite 동시 쓰기 경쟁 테스트 부재 (낮음)
- 실제 2세션 동시 전이(경쟁) 시나리오 자동화 테스트가 없다.
  StaleDataError 처리는 단일 테스트에서 주입 방식으로만 검증.
- 완화: 시스템 설계 10.1 "단일 프로세스·단일 쓰기" 전제,
  데이터-모델 10.1 위험 항목으로 이미 승인 관리.
- 조치: 멀티프로세스 확장 시 재평가.

### 2.2 Alembic downgrade 데이터 손실 (낮음)
- `downgrade()`가 `DROP TABLE`을 실행(개발용). 프로덕션 실행 시 데이터 손실.
- 완화: 실행계획상 1단계는 `upgrade head`만 수행, 복구 절차는
  `runtime/db/**` 파일 복사(설계 10.3). 운영 시 downgrade 금지 안내 필요.

### 2.3 UTCDateTime TypeDecorator 커버리지 (낮음)
- `process_bind_param`/`process_result_value` 왕복 변환에 대한
  명시적 단위 테스트가 없음. 통합 흐름에서 간접 검증은 됨.
- 완화: 통합 테스트에서 completion_date/changed_at 저장·조회 정상 확인.

### 2.4 Enum `native_enum=False` ALTER COLUMN 제한 (낮음)
- SQLite는 컬럼 길이 변경(ALTER COLUMN) 미지원.
  상태값 변경 시 마이그레이션 재설계 필요. 1단계 고정 4상태라 영향 없음.

### 2.5 UI/화면 기능 미구현 (정보)
- 현재 코드베이스에 HTML/Jinja 템플릿·정적 에셋·화면 라우트 없음
