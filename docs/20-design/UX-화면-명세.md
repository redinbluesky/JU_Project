## 1. 화면 흐름

### 1.1 접수폼

**목적**: 현장 담당자가 복지용구 수거를 접수한다.

**사용자 행동**:
1. 사업소 선택
2. 수거 희망일 선택
3. 수거 장소 유형 선택 (사업소/자택)
4. 수거 주소 입력
5. 품목 수량 입력 (전동침대, 휠체어, 기타 소형 용구)
6. 접수 생성

**화면 흐름**:
```
[접수폼 화면]
├── 사업소 선택 (드롭다운 또는 라디오 버튼)
├── 수거 희망일 선택 (날짜 입력)
├── 수거 장소 유형 선택 (사업소/자택)
├── 수거 주소 입력 (항상 활성화)
├── 품목 수량 입력 (카운터 형태)
│   ├── 전동침대 수량
│   ├── 휠체어 수량
│   └── 기타 소형 용구 수량
└── 접수 생성 버튼
```

### 1.2 접수 목록/상세

**목적**: 관리자가 접수 내역을 조회하고 상세 정보를 확인하며 상태를 변경한다.

**사용자 행동**:
1. 목록에서 필터 적용 (기간, 사업소, 상태)
2. 목록에서 접수 건 선택
3. 상세 정보 확인
4. 픽업 담당 기사 선택·지정 또는 변경
5. 상태 변경 (접수대기 → 수거예정 → 입고/소독중 → 소독완료 → 배송완료)
6. 처리 이력 타임라인에서 상태별 처리 시각·처리자·처리 내역 확인
7. 소독완료 상태부터 PDF 다운로드

**기사 지정 기준**:
- 기사 선택 항목은 `기사명 + 연락처`를 함께 표시한다.
- 상세 화면에는 현재 지정 기사, 연락처, 지정 시각을 표시한다.
- 기사 변경 시 이전 기사와 새 기사, 변경 시각을 처리 이력/감사 이력에 남긴다.
- 기사 미지정 상태는 색상에 의존하지 않고 `미지정` 텍스트와 안내 문구로 표시한다.

**화면 흐름**:
```
[목록 화면]
├── 필터 영역 (기간, 사업소, 상태)
├── 접수 목록 테이블
│   ├── 접수번호
│   ├── 사업소
│   ├── 수거 희망일
│   ├── 상태
│   └── 전체 수량
└── 엑셀 다운로드 버튼

[상세 화면]
├── 접수번호
├── 사업소
├── 수거 희망일
├── 수거 장소 유형과 주소
├── 품목별 수량
├── 현재 상태 진행 표시 (아이콘·텍스트 사이 `var(--space-3)` 이상 간격)
├── 픽업 담당 기사 지정 영역
│   ├── 기사 선택 (기사명 + 연락처)
│   ├── 현재 지정 기사·연락처
│   └── 지정/변경 시각
├── 상태 변경 버튼 (다음 단계만 활성화)
├── 처리 이력 타임라인
│   ├── 상태명
│   ├── 처리 시각
│   ├── 처리자/기사
│   └── 처리 내역 메모
├── 생성 시각
├── 완료일
└── PDF 다운로드 버튼 (소독완료 상태부터)
```

**상태 진행 표시**:
- 순서: `접수대기 → 수거예정 → 입고/소독중 → 소독완료 → 배송완료`.
- 현재 단계는 상태명·현재 표시를 함께 제공하며, 완료/미진행은 아이콘과 텍스트를 병행한다.
- 상태 아이콘과 상태 텍스트는 오인 방지를 위해 충분한 간격을 둔다.
- 상태는 바로 다음 단계로만 전이하며, 중간 단계 건너뛰기와 역방향 변경은 제공하지 않는다.

**처리 이력 타임라인**:
- 모든 상태 전이마다 처리 시각, 처리자 또는 기사, 처리 내역 메모를 한 항목으로 기록한다.
- 최신 이력이 위에 오며, 시각은 `YYYY-MM-DD HH:mm` 형식으로 표시한다.
- 이력은 읽기 전용이며 임의 수정·삭제 버튼을 제공하지 않는다.

### 1.3 통계 대시보드

**목적**: 관리자가 접수 현황을 집계하여 파악한다.

**사용자 행동**:
1. 기간 선택
2. 통계 항목 확인

**화면 흐름**:
```
[통계 대시보드]
├── 기간 선택 필터
├── 기간별 접수 건수
├── 사업소별 접수 건수
├── 상태별 접수 건수
├── 전체 품목 총수량
├── 전동침대 총수량
├── 휠체어 총수량
└── 기타 소형 용구 총수량
```

## 2. 필드, 검증 규칙, 오류 상태

### 2.1 접수폼 필드

| 필드 | 타입 | 필수 | 검증 규칙 | 오류 메시지 |
|------|------|------|-----------|------------|
| 사업소 | 선택 | 예 | 고정된 1~3개 중 선택 | 사업소를 선택하세요 |
| 수거 희망일 | 날짜 | 예 | 오늘 이후 날짜만 | 오늘 이후 날짜를 선택하세요 |
| 수거 장소 유형 | 선택 | 예 | 사업소 또는 자택 | 수거 장소 유형을 선택하세요 |
| 수거 주소 | 텍스트 | 예 | 항상 입력 필수 | 주소를 입력하세요 |
| 전동침대 수량 | 정수 | 예 | 0 이상의 정수, 최소 한 품목이 1 이상 | 전동침대 수량을 입력하세요 |
| 휠체어 수량 | 정수 | 예 | 0 이상의 정수 | 휠체어 수량을 입력하세요 |
| 기타 소형 용구 수량 | 정수 | 예 | 0 이상의 정수 | 기타 소형 용구 수량을 입력하세요 |

**검증 로직**:
- 모든 품목 수량이 0이면 접수가 거부된다.
- 음수 또는 정수가 아닌 수량은 거부된다.
- 오늘 이전 날짜는 거부된다.
- 사업소, 수거 희망일, 장소 유형, 주소가 없으면 접수가 거부된다.
- 주소는 장소 유형과 무관하게 항상 필수 입력.

### 2.2 관리자 기사 지정 필드

| 필드 | 타입 | 필수 | 검증 규칙 | 오류/상태 메시지 |
|------|------|------|-----------|----------------|
| 픽업 담당 기사 | 선택 | 지정 시 예 | 기사 마스터에서 1명 선택, 기사명+연락처 표시 | 담당 기사를 선택해 주세요 |
| 기사 연락처 | 읽기 전용 | 자동 | 선택한 기사 마스터 연락처를 표시, 직접 수정 불가 | 기사 연락처를 확인할 수 없습니다 |
| 지정 시각 | 읽기 전용 | 자동 | 지정 확정 시각을 기록 | 미지정 |
| 처리 내역 메모 | 여러 줄 텍스트 | 상태 변경 시 예 | 상태 변경 사유/현장 메모, 저장 후 이력에서 읽기 전용 | 처리 내역을 입력해 주세요 |

### 2.3 상태 흐름 및 처리 이력

| 현재 상태 | 다음 상태 | 변경 시각 기록 | 처리자/기사 | 화면 알림 |
|-----------|----------|----------------|-------------|----------|
| 접수대기 | 수거예정 | 예 | 예 | 예 |
| 수거예정 | 입고/소독중 | 예 | 예 | 예 |
| 입고/소독중 | 소독완료 | 예 | 예 | 예 |
| 소독완료 | 배송완료 | 예 | 예 | 예 |
| 배송완료 | (종료) | 완료일 기록 | 예 | 예 |

**규칙**:
- 현재 상태의 바로 다음 상태로만 변경 가능
- 중간 상태를 건너뛰는 변경 거부
- 역방향 변경 거부
- 상태 변경 전 처리 내역 메모 입력을 요구한다.
- 기사 지정·변경과 상태 전이·메모 변경은 감사 이력으로 남긴다.
- 처리 이력은 append-only이며 화면에서 수정·삭제할 수 없다.
- 접수 정보는 접수 상태에서만 수정 가능
- 접수 삭제 허용 안 함

## 3. 모바일·태블릿·PC 레이아웃

> 반응형 기준은 승인된 `DEC-008`을 따른다.
> - 모바일: `<= 767px`
> - 태블릿: `768~1279px`
> - PC: `>= 1280px`

### 3.1 모바일 레이아웃 (`<= 767px`, 375px 기준)

**공통 내비게이션**:
- 햄버거 메뉴로 주요 메뉴를 열고 닫는다.
- 좌측 고정 메뉴는 사용하지 않는다.

**접수폼**:
- 모든 필드를 세로로 배치
- 각 필드 레이블 → 입력 필드 순서
- 품목 수량은 카운터 형태 (증감 버튼 + 입력란)
- 접수 생성 버튼은 하단 고정하지 않는다.
- 접수 생성 버튼은 폼 흐름 안에 배치하는 일반 버튼이며, 컨테이너 기준 전체 폭으로 표시한다.

**목록 화면**:
- 품목/접수 목록은 테이블이 아닌 카드형 목록으로 표시한다.
- 각 카드는 접수번호, 상태, 수거 희망일 등 핵심 정보를 우선 표시하고, 상세 정보로 진입할 수 있어야 한다.
- 가로 스크롤에 의존하지 않는다.

**상세 화면**:
- 필드를 세로로 배치
- 상태 진행 표시와 아이콘·텍스트 사이 간격을 `var(--space-3)` 이상 유지
- 기사 선택은 전체 폭 선택 컨트롤로 제공하고, 선택 항목에 기사명+연락처를 표시
- 현재 지정 기사·연락처·지정 시각을 선택 영역 바로 아래에 표시
- 상태 변경 버튼은 화면 하단에 고정하여 유지
- 상태 변경 전 메모 입력 영역과 명시적 오류 메시지 제공
- 처리 이력은 최신순 세로 타임라인으로 표시하며 가로 스크롤에 의존하지 않음
- PDF 다운로드 버튼은 소독완료 상태부터 표시

**통계 대시보드**:
- 각 통계 항목을 카드 형태로 세로 배치
- 숫자는 크게 표시

### 3.2 태블릿 레이아웃 (`768~1279px`)

**공통 내비게이션**:
- 모바일과 동일하게 햄버거 메뉴를 사용한다.
- PC용 좌측 고정 메뉴는 사용하지 않는다.

**접수폼**:
- 화면 폭에 따라 필드를 1열 또는 2열로 배치한다.
- 품목 수량은 가용 폭이 충분하면 가로로, 부족하면 세로로 배치한다.
- 주소 입력란은 가능한 경우 전체 폭으로 표시한다.
- 접수 생성(신청) 버튼은 하단 고정 없이 일반 버튼으로 표시하고 우측 정렬한다.

**목록 화면**:
- `768~959px`에서는 카드형 목록을 사용한다.
- `960~1279px`에서는 접수번호, 수거 희망일, 상태 등 핵심 열 중심의 축약 테이블을 사용하며, 상세 정보는 상세 화면에서 확인한다.
- 카드형 목록과 축약 테이블 모두 가로 스크롤에 의존하지 않는다.

**상세 화면**:
- 가용 폭에 따라 1열 또는 좌우 레이아웃으로 배치한다.
- 상태 변경 버튼은 일반 버튼으로 배치하며 화면 하단에 고정하지 않는다.
- PDF 다운로드 버튼은 소독완료 상태부터 표시

**통계 대시보드**:
- 가용 폭에 따라 1열 또는 2열 카드 그리드로 배치한다.
- 숫자는 크게 표시

### 3.3 PC 레이아웃 (`>= 1280px`)

**공통 내비게이션**:
- 좌측 메뉴를 고정하여 표시한다.
- PC에서만 좌측 고정 메뉴를 사용한다.

**접수폼**:
- 사업소, 수거 희망일, 장소 유형을 가로로 배치
- 품목 수량을 가로로 배치
- 주소 입력란은 넓게 표시

**목록 화면**:
- 접수 목록은 테이블을 유지하고 콘텐츠 영역 전체 너비로 표시한다.
- 필터 영역을 상단에 배치
- 열은 모두 표시 (접수번호, 사업소, 수거 희망일, 상태, 전체 수량)

**상세 화면**:
- 좌우 레이아웃: 좌측에 기본 정보, 우측에 상태 정보
- 상태 진행 표시·기사 지정·처리 이력은 우측 상태 정보 영역에 배치
- 기사 선택 항목과 현재 지정 정보에 기사명+연락처를 함께 표시
- 상태 변경 전 처리 내역 메모를 입력하며 오류는 필드 아래에 표시
- 상태 변경 버튼은 우측 하단에 배치
- 처리 이력은 최신순 타임라인으로 표시하고 각 항목에 상태명·처리 시각·처리자/기사·메모를 포함

**통계 대시보드**:
- 통계 항목을 2열 또는 3열 그리드로 배치
- 각 카드에 숫자를 크게 표시

### 3.4 반응형 규칙

- `<= 767px`에서는 햄버거 메뉴, 세로형 접수폼, 카드형 목록을 사용한다.
- `768~1279px`에서는 햄버거 메뉴를 사용하고, 목록은 화면 폭에 따라 축약 테이블 또는 카드형으로 전환한다.
- `>= 1280px`에서는 좌측 고정 메뉴와 전체 열 테이블을 유지한다.
- 모바일 신청 버튼은 하단 고정 없이 일반 버튼으로 표시하며, 컨테이너 기준 전체 폭으로 표시한다.
- 태블릿 신청 버튼은 하단 고정 없이 일반 버튼으로 표시하고 우측 정렬한다.
- 모바일 상세의 상태 변경 버튼은 화면 하단에 고정하여 유지한다.
- 가로 스크롤에 의존하지 않도록 모든 화면 설계
- 핵심 흐름은 모바일에서도 수행 가능

## 4. 화면 알림

**발생 시점**:
- 접수 생성
- 기사 지정 또는 기사 변경
- 수거예정 전환
- 입고/소독중 전환
- 소독완료 전환
- 배송완료 전환

**표시 방식**:
- 화면 상단에 알림 메시지 표시
- 5초 후 자동 사라짐
- 색상만으로 상태 구분하지 않음 (아이콘 + 텍스트)
- 스크린리더 지원: role="status", aria-live="polite" 속성 적용
- 알림 텍스트는 접수번호, 변경한 대상, 변경 결과를 명시적으로 포함
  - 예: `접수번호 1234, 담당 기사 홍길동(010-0000-0000)으로 지정했습니다.`
  - 예: `접수번호 1234, 수거예정으로 전환했습니다.`

## 5. PDF 다운로드

**조건**: 소독완료 상태부터 다운로드 가능
**형식**: 빈 PDF (1단계에서는 실제 공단 양식 데이터 삽입 안 함)
**흐름**: 상세 화면에서 PDF 다운로드 버튼 클릭 → 파일 다운로드

## 6. 엑셀 다운로드

**조건**: 현재 필터 결과 기준
**필수 열**:
- 접수번호
- 사업소
- 수거 희망일
- 수거 장소 유형
- 수거 주소
- 전동침대 수량
- 휠체어 수량
- 기타 소형 용구 수량
- 상태
- 완료일

**검증**: 엑셀 값은 화면 및 저장 데이터와 일치해야 함

| 스크린 리더 | 레이블과 상태 읽힘 |

## 8. 구현 인수 조건

### 8.1 접수

1. 초기 등록 사업소를 선택
2. 오늘 이후의 수거 희망일 선택
3. 사업소 또는 자택 선택, 주소 입력
4. 최소 한 품목 수량 1 이상 입력
5. 접수 생성
6. 접수번호, 접수 상태, 생성 시각 저장
7. 화면 알림 표시

### 8.2 입력 검증

- 모든 품목 수량이 0이면 접수 거부
- 음수 또는 정수가 아닌 수량 거부
- 오늘 이전 날짜 거부
- 사업소, 수거 희망일, 장소 유형, 주소 없으면 접수 거부

### 8.3 상태 흐름·기사·이력

1. 접수대기에서 수거예정으로만 변경 가능
2. 수거예정에서 입고/소독중으로만 변경 가능
3. 입고/소독중에서 소독완료로만 변경 가능
4. 소독완료에서 배송완료로만 변경 가능
5. 상태 변경 전 처리 내역 메모 미입력 시 오류를 표시하고 전환하지 않음
6. 각 변경 시각·처리자/기사·처리 내역이 타임라인에 최신순으로 기록됨
7. 처리 이력은 수정·삭제할 수 없음
8. 기사 선택 목록에 기사명+연락처가 함께 표시됨
9. 기사 지정·변경 시 현재 기사·연락처·지정 시각이 상세에 표시됨
10. 기사 변경 시 이전 기사와 새 기사 정보가 이력에 남음
11. 상태 진행 아이콘과 텍스트 사이 간격이 충분하고 색상만으로 구분하지 않음
12. 소독완료 상태부터 PDF 다운로드
13. 중간 상태 건너뛰기와 역방향 변경 거부 확인
14. 배송완료 시 완료일 기록 확인

### 8.4 데이터 보존

1. 애플리케이션 종료
2. 애플리케이션 재실행
3. 접수 정보, 현재 상태, 모든 상태 변경 시각, 완료일 유지 확인

### 8.5 조회·통계·엑셀

1. 기간·사업소·상태 필터 결과 저장 데이터와 일치 확인
2. 접수 건수와 전체·종류별 품목 수량 일치 확인
3. 엑셀 다운로드
4. 엑셀 각 필수 열과 값 화면 및 저장 데이터와 일치 확인

### 8.6 화면

- PC Chrome에서 접수부터 배송완료까지 수행 가능
- 모바일 너비에서 가로 스크롤에 의존하지 않고 핵심 흐름 수행 가능
- 모든 입력에 식별 가능한 레이블과 검증 오류 메시지 있음
- 상태를 색상만으로 구분하지 않음
