# WP-12 실행 지시서 — 전체 업무 흐름 통합검증

담당: `local-builder` | 수정 허용 경로: `tests/test_integration_flow.py`, `tests/conftest.py`(필요한 경우만), `app/**`(통합검증 중 발견한 결함 수정 시에만)

## 배경

WP-05~WP-11이 완료됐고 현재 전체 회귀 테스트는 116개 통과했다. 이번에는 기능을 하나의 업무 흐름으로 연결해 검증한다. 새 기능을 무리하게 추가하지 말고, 실패하면 원인을 수정한 뒤 테스트를 다시 실행하라.

## 통합 시나리오

임시 SQLite 파일 DB를 사용해 runtime/db/ju-project.db를 오염시키지 마라. TestClient와 dependency override 또는 테스트용 설정으로 실제 FastAPI 라우터를 호출하라.

1. 사업소·RequestNoCounter 시딩
2. 정상 접수 생성 → 201, `RECEIVED`
3. 오류 입력(전체 수량 0 또는 오늘 날짜) → 422, DB에 추가 저장 없음
4. 접수 수정 → 200, DB 값 변경 확인
5. `RECEIVED → PICKED_UP` → 200, 이력 2건
6. `PICKED_UP → DISINFECTED` → 200, 이력 3건
7. `DISINFECTED` 상태 PDF 다운로드 → 200, PDF 헤더/파일 크기/프로토타입 표시 확인
8. `DISINFECTED → DELIVERED` → 200, completion_date 기록
9. 배송완료 이후 PDF 재다운로드 → 200
10. 목록 필터와 통계 결과 비교
11. 같은 필터로 XLSX 다운로드 → 200, 10개 헤더, 행 수와 목록 일치, DB 값 대조
12. XLSX의 모든 셀에 formula data_type이 없는지 확인
13. 애플리케이션/세션 종료 후 같은 SQLite 파일을 새 engine/session으로 다시 열어 Request와 상태 이력 4건이 그대로 보존되는지 확인

## 필수 테스트

`tests/test_integration_flow.py`에 위 흐름을 순서대로 검증하는 통합 테스트를 작성하라. 최소 다음을 포함하라:

- 정상 전체 흐름 1개
- 오류 저장 방지 1개
- 필터·통계·엑셀 정합성 1개
- SQLite 재오픈 후 데이터·이력 보존 1개

PDF/XLSX는 tmp_path 출력 경로를 주입하거나 테스트 종료 후 임시 DB·파일을 삭제하라.

## 실행 증거

반드시 실행:
```
uv run pytest tests/test_integration_flow.py -v
uv run pytest tests/ -q
```

추가로 가능하면 실제 서버 기동 명령과 httpx/curl 결과도 보고하라. 통합 테스트에서 실제로 검증한 범위와 수동 실행 범위를 구분하라.
