# WP-07 실행 지시서 (B) — 상태전이 API + StaleDataError/중복 요청 검증

담당: `local-builder` | 수정 허용 경로: `app/main/schemas/request.py`, `app/main/services/request_service.py`, `app/main/api/requests.py`, `tests/test_status_transition_api.py`

## 이번 청크 범위

WP-07-A의 `transition_request_status()`를 API에 연결한다. 목록/통계/PDF/엑셀은 구현하지 마라. 모델 파일과 Alembic 파일도 수정하지 마라.

## 구현

### 1. 스키마

`app/main/schemas/request.py`에 상태 전이 요청 스키마를 추가하라.

- `target_status: RequestStatus`

### 2. API

`app/main/api/requests.py`에 다음 라우터를 추가하라.

```text
PATCH /api/requests/{request_id}/status
```

요구사항:
- 성공: 200 + RequestOut
- `ValueError`: 409
- `StaleDataError`: 409, "다른 요청이 먼저 변경했으므로 다시 조회 후 재시도" 취지의 메시지
- 그 외 예외: rollback 후 500
- 기존 POST/PATCH 수정 API 동작은 깨뜨리지 마라

### 3. 서비스 보완

`transition_request_status()`에서 commit 중 발생하는 `StaleDataError`가 세션 rollback 후 호출자에게 전달되도록 보완하라. 자동 재시도는 구현하지 마라. 데이터 모델 승인(DEC-007)은 재시도 안내만 제공하는 방식이다.

중복 상태 요청은 기존 ValueError 경로로 거부하고 상태·이력 불변을 유지하라.

## pytest 필수

`tests/test_status_transition_api.py`를 새로 작성하라. 기존 테스트 파일은 수정하지 마라.

최소 테스트:
1. `RECEIVED → PICKED_UP` API 성공 200
2. `RECEIVED → DISINFECTED` 건너뛰기 409
3. 역방향 전환 409
4. 동일 상태 중복 전환 409 + 이력 개수 불변
5. `DELIVERED` 이후 전환 409
6. 존재하지 않는 request id 409
7. `StaleDataError`를 서비스에서 유도하거나 monkeypatch하여 API가 409로 변환하는지 확인
8. 기존 접수 생성/수정 API 회귀

테스트는 임시 SQLite + StaticPool 또는 기존 패턴을 사용하고, RequestNoCounter와 초기 사업소를 시딩하라.

## 검증 명령

반드시 실행:
```
uv run pytest tests/test_status_transition_api.py -v
uv run pytest tests/ -q
```
