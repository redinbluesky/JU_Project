# WP-09 실행 지시서 — 소독완료 이후 PDF 다운로드 흐름 + pytest

담당: `local-builder` | 수정 허용 경로: `app/main/services/`, `app/main/api/requests.py`, `tests/test_pdf_download.py`

## 배경

WP-08-A까지 완료됐고 전체 테스트 75개가 통과했다. 이번에는 PDF 다운로드 흐름만 구현한다. 통계·엑셀·외부 공유 URL은 구현하지 마라.

## 요구사항

### 엔드포인트

```text
GET /api/requests/{request_id}/pdf
```

### 권한 규칙

- `RECEIVED`: 거부
- `PICKED_UP`: 거부
- `DISINFECTED`: 허용
- `DELIVERED`: 허용
- 미존재: 404
- 거부 응답: 409 또는 403 중 하나를 선택하고 보고서에 명시
- 서버가 요청 시점에 DB에서 현재 상태를 재조회해 판단

### PDF 내용

- reportlab 사용
- `runtime/pdf/`에 생성
- 실제 유효한 PDF 응답(`Content-Type: application/pdf`)
- 문서에 다음 표시 포함:
  `기술 프로토타입 - 공단 제출용 아님`
- 접수번호와 현재 상태도 포함
- 1단계에서는 외부 공유 URL, 만료, 취소 기능을 만들지 않는다

## 구현 권장 위치

- `app/main/services/pdf_service.py`: `generate_request_pdf(request) -> Path` 또는 bytes
- `app/main/api/requests.py`: PDF GET 라우터
- 기존 API와 모델/Alembic 파일은 변경하지 마라

## pytest 필수

`tests/test_pdf_download.py` 신규 작성. 임시 SQLite + StaticPool, 사업소·카운터를 시딩하라.

최소 테스트:
1. RECEIVED PDF 거부
2. PICKED_UP PDF 거부
3. DISINFECTED PDF 200 + application/pdf + `%PDF` 헤더 + 크기 > 0
4. DELIVERED PDF 200
5. 미존재 id 404
6. PDF 응답/파일에 프로토타입 표시 검증(압축되지 않은 PDF 또는 생성 함수 결과 기준)
7. 기존 POST/PATCH/status/query API 회귀

실제 runtime 디렉터리를 오염시키지 않도록 테스트 파일은 tmp_path를 사용하거나 서비스 출력 경로를 주입하라. 단, 개발 실행 시 실제 PDF는 `runtime/pdf/`에 생성되어야 한다.

## 검증 명령

반드시 실행:
```
uv run pytest tests/test_pdf_download.py -v
uv run pytest tests/ -q
```
