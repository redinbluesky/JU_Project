# WP-14-B2 지시서 — Wanted 기반 목록·상세 화면

담당: `local-builder`
수정 허용 경로: `app/server.py`, `app/templates/requests/list.html`, `app/templates/requests/detail.html`, `app/static/css/app.css`, `app/static/js/app.js`, `tests/test_ui_list_detail.py`

## 배경

WP-14-B0 Wanted CSS 토큰과 WP-14-B1 접수폼 UI가 완료됐다.
- Wanted CSS 토큰 원본 일치
- 접수폼 실제 브라우저 렌더링 확인
- 전체 회귀 148개 통과

이번에는 **목록·상세 화면만** 구현한다. 통계 화면은 다음 B3 청크다.

## 화면 경로

- `GET /admin/requests` — 목록
- `GET /admin/requests/{id}` — 상세

## 목록 화면

Wanted 토큰의 정보 중심·border-first 스타일을 적용하라.

필수:
- 기간(from/to), 사업소, 상태 필터
- 필터 적용 시 기존 `GET /api/requests` 호출
- 접수번호·사업소·수거 희망일·상태·전체 수량 테이블/리스트
- 상태는 텍스트와 badge/chip 병기
- 상세 링크
- 엑셀 다운로드 링크(`/api/requests/export`)
- 0건 empty state
- `role="status"`, `aria-live="polite"`
- 모바일 375px에서 가로 스크롤 없는 responsive list/card

## 상세 화면

필수:
- 접수번호·사업소·수거 희망일·장소·주소·품목별 수량
- 현재 상태와 상태 이력 표시
- 상태 변경 버튼: 현재 상태의 바로 다음 상태만 표시/활성화
- 버튼 클릭 시 `/api/requests/{id}/status` 호출
- `DISINFECTED`/`DELIVERED`에서 PDF 다운로드 버튼 활성화
- 접수 상태에서 수정 링크 또는 수정 화면 링크
- 성공/오류를 `role=status`, `aria-live=polite`로 표시

## 구현 규칙

- Jinja2 + Vanilla JS 유지
- React/_ds_bundle.js/CDN 사용 금지
- 기존 API와 접수폼을 깨뜨리지 마라
- 실제 개인정보·Wanted 브랜드 자산 사용 금지
- 목록 화면은 Operate, 상세는 Inspect 표면으로 구성

## 테스트

`tests/test_ui_list_detail.py` 신규 작성:
1. 목록 GET 200 + 필터 입력/테이블/상세/엑셀 링크
2. 목록 empty state
3. 상세 GET 200 + 필수 필드/상태 이력
4. 미존재 상세 404 또는 안전한 오류 화면
5. 상태 버튼/PDF 버튼 조건 존재
6. role=status·aria-live
7. 모바일 CSS media query 및 가로 overflow 방지
8. 기존 API 회귀
