## 요구사항

### 목록 API

```text
GET /api/requests
```

쿼리 파라미터:
- `pickup_date_from: date | None`
- `pickup_date_to: date | None`
- `business_office_id: int | None`
- `current_status: RequestStatus | None`

규칙:
- 기간 필터는 반드시 `pickup_date` 기준
- 입력된 조건은 AND로 결합
- 정렬은 `pickup_date ASC, id ASC`
- 결과는 DB 원본과 동일해야 함
- 응답은 최소 `items: list[RequestOut]`, `total: int` 형태
- `from`이 `to`보다 늦으면 422 또는 400으로 명시적 거부

### 상세 API

```text
GET /api/requests/{request_id}
```

- 존재: 200 + RequestOut
- 미존재: 404
- 현재 상태, 완료일, 수량, 주소, 생성/수정 시각 등 전체 필수 필드 포함

## 구현 권장 위치

- `request_service.py`: `list_requests(...)`, `get_request(...)`
- `requests.py`: GET 라우터 추가
- `request.py`: 필터용 Pydantic 모델 또는 FastAPI Query 검증 추가
- 기존 POST/PATCH/status API는 변경하지 마라

## pytest 필수

`tests/test_request_query.py` 신규 작성. 임시 SQLite + StaticPool, 사업소 2개와 서로 다른 pickup_date/status 접수 4건을 시딩하라.

최소 테스트:
1. 전체 목록 개수·정렬
2. `pickup_date_from` 필터가 생성일이 아닌 수거희망일을 기준으로 동작
3. `pickup_date_to` 필터
4. 사업소 필터
5. 상태 필터
6. 기간+사업소+상태 복합 필터
7. from > to 거부
8. 상세 200 및 전체 필드 확인
9. 미존재 상세 404
10. 기존 POST/PATCH/status API 회귀

## 검증 명령

반드시 실행:
```
uv run pytest tests/test_request_query.py -v
uv run pytest tests/ -q
```
