## 거부해야 할 5가지 케이스 (QA-005~009)

1. **모든 품목 수량 0** — 전동침대=0, 휠체어=0, 기타=0이면 거부 (합계 >= 1 필수, 데이터모델 CheckConstraint와 동일 원칙을 API 레벨에서도 검증)
2. **음수 수량** — 전동침대/휠체어/기타 중 하나라도 음수면 거부
3. **정수가 아닌 수량** — 소수(1.5) 또는 문자열이 들어오면 거부 (Pydantic이 기본으로 처리하는지 확인, 안 되면 명시 검증 추가)
4. **오늘 이전 날짜** — `pickup_date`가 오늘 날짜이거나 과거면 거부 (오늘+1일부터 허용)
5. **필수값 누락** — `business_office_id`, `pickup_date`, `pickup_location_type`, `pickup_address` 중 하나라도 없으면 거부

## 작업

### 1. `app/main/schemas/request.py`에 Pydantic validator 추가
- `RequestCreate`에 `@field_validator` 또는 `@model_validator`(Pydantic v2)로:
  - 수량 합계 >= 1 검증
  - `pickup_date`가 내일(오늘+1일) 이후인지 검증 — "오늘 이전"이 아니라 범위문서 원문 그대로: 사전조건에 "오늘+1일부터 허용"이 명시되어 있는지 다시 확인하고 그 기준을 정확히 따르라. 애매하면 QA-008 문구("오늘 이전 날짜 거부")를 그대로 따라 오늘 이후(오늘 포함)는 허용, 어제 이전만 거부하는 것으로 구현하고 완료 보고에 어느 쪽으로 구현했는지 명시하라.
  - 필수 문자열 필드 빈 문자열 거부(주소 등)

### 2. API 오류 응답
- 검증 실패 시 FastAPI가 자동으로 422를 반환하는 것을 그대로 활용 (Pydantic ValidationError → 422)
- `app/main/api/requests.py`의 try/except가 422를 500으로 덮어쓰지 않는지 확인 (Pydantic 검증은 라우터 진입 전에 이미 걸러지므로 문제없을 것으로 예상되나 실제로 확인하라)

### 3. pytest (`tests/test_request_validation.py`) — 필수
최소 6개 이상 테스트, 5가지 케이스 각각 최소 1개 + 정상 케이스 회귀 확인 1개:
- `test_reject_all_quantities_zero`
- `test_reject_negative_quantity`
- `test_reject_non_integer_quantity`
- `test_reject_past_date` (또는 오늘 날짜, 지시서 2번 항목에서 정한 기준대로)
- `test_reject_missing_required_field` (여러 필드 중 하나씩 빠뜨린 케이스 2~3개면 더 좋음)
- 각 실패 케이스에서 **DB에 아무것도 저장되지 않았는지**(rows count 불변) 확인하는 assert 포함
