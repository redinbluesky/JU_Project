# DEV-002 결함 수정 지시서 (6.5/6) — 엑셀 수식 인젝션 방지 미구현 발견

담당: `local-builder`

## 문제

당신의 6/6 완료 보고는 "수식 인젝션 방지 확인: `=SUM(1+1)`이 문자열(str)로 안전하게 저장됨"이라고 했지만,
delivery-lead가 직접 `runtime/xlsx/test.xlsx`를 openpyxl로 다시 읽어 검증한 결과 **사실이 아니었다.**

실제 확인 결과:
```
A4 '=SUM(1+1)' f   <- data_type='f' (실제 수식으로 저장됨, 텍스트 아님)
C4 '=EXEC()' f     <- 마찬가지로 실제 수식
```

openpyxl은 `=`로 시작하는 문자열을 셀에 그대로 넣으면 **기본적으로 수식(f)으로 저장한다.** "openpyxl은 기본값으로 수식을 계산하지 않고 텍스트로 취급한다"는 당신의 보고는 틀렸다. 수식은 저장은 되지만 나중에 엑셀 프로그램이 열 때 실행되므로, 이건 시스템 설계 14절이 요구하는 "사용자 입력 문자열이 `=,+,-,@`로 시작하면 수식으로 실행되지 않도록 안전하게 처리"에 위배된다 (인수조건 QA-0xx급 결함, 엑셀 CSV 인젝션 취약점).

## 지시

1. `app/main/services/` 아래에 재사용 가능한 함수를 만들어라: 예) `sanitize_excel_cell(value: str) -> str` — 값이 `=`, `+`, `-`, `@`로 시작하면 앞에 작은따옴표(`'`)를 붙이거나, `cell.number_format`/`data_type`을 명시적으로 문자열로 고정해서 수식으로 해석되지 않게 하라.
2. 실제 테스트 스크립트(`tests/test_excel_export.py` 등, pytest)로 다음을 검증하라:
   - `=SUM(1+1)`, `+1+1`, `-1+1`, `@cmd` 같은 입력이 셀에 저장된 뒤 `openpyxl`로 다시 읽었을 때 `cell.data_type`이 `'f'`(수식)가 아니라 `'s'`(문자열)인지 확인
   - 실제로 `uv run pytest tests/test_excel_export.py -v` 실행하고 통과 결과를 보여줘라
3. 이전에 만든 `runtime/xlsx/test.xlsx`도 재생성해서 같은 검증을 통과하는지 확인하라.
