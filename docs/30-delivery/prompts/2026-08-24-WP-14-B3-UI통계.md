# WP-14-B3 지시서 — Wanted 기반 통계 화면만 구현

담당: `local-builder`
수정 허용 경로: `app/server.py`, `app/templates/dashboard/index.html`, `app/static/css/app.css`, `tests/test_ui_dashboard.py`

## 범위 제한

통계 대시보드 화면 하나만 구현한다. 기존 접수폼·목록·상세 화면과 API 로직은 깨뜨리지 마라. PPT 작성과 브라우저 전체 검증은 다음 단계다.

## 경로

```text
GET /admin/dashboard
```

## 구현

- 기간 from/to 필터
- 기존 `GET /api/statistics`와 동일한 필터 기준 사용
- 전체 접수 건수
- 사업소별 접수 건수
- 상태별 접수 건수
- 전체 품목 수량
- 전동침대·휠체어·기타 소형 수량
- 0건 empty state
- Wanted 토큰 기반 정보 중심 Monitor 화면
- 과도한 큰 숫자·장식용 gradient 금지
- 상태는 색상과 텍스트 병기
- `role="status"`, `aria-live="polite"`
- 모바일 375px에서 가로 스크롤 없음

## 구현 주의

`app/server.py`에서 FastAPI Request와 SQLAlchemy Request는 alias로 구분하라:

```python
from fastapi import Request
from app.main.models.models import Request as RequestModel
```

통계 값은 기존 service `get_statistics_summary()`를 재사용하라. 별도 집계 원본을 만들지 마라.

## 테스트

`tests/test_ui_dashboard.py` 신규 작성:
1. GET `/admin/dashboard` 200
2. 기간 필터 input과 통계 항목 텍스트 존재
3. 전체/사업소/상태/품목 값 렌더링
4. 0건 결과 구조
5. role=status·aria-live
6. Wanted CSS 연결
7. 375px responsive CSS 확인
8. 기존 접수폼·목록·상세/API 회귀

## 실행

```
uv run python -c "import app.server; print('import ok')"
uv run pytest tests/test_ui_dashboard.py -v
uv run pytest tests/ -q
```

실제 파일 작성과 테스트 실행 전에는 완료라고 보고하지 마라.
