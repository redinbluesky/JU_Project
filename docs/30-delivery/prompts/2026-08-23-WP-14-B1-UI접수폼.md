# WP-14-B1 지시서 — Wanted 토큰 기반 공통 레이아웃 + 접수폼만

담당: `local-builder`
수정 허용 경로: `app/server.py`, `app/templates/base.html`, `app/templates/requests/new.html`, `app/static/css/app.css`, `app/static/js/app.js`, `tests/test_ui_form.py`

## 범위 제한

이번 청크는 공통 레이아웃과 접수폼만 구현한다. 목록·상세·통계는 다음 청크에서 한다. React/_ds_bundle.js는 사용하지 마라.

## 구현

1. `app/server.py`에 Jinja2Templates 설정과 `GET /requests/new` 페이지 라우트를 추가한다. 기존 API 라우터와 health를 유지한다.
2. `templates/base.html`:
   - lang=ko, viewport
   - `/static/css/wanted.css`와 `/static/css/app.css` 연결
   - 공통 header
   - `{% block content %}`
   - `<div id="live-status" role="status" aria-live="polite"></div>`
3. `templates/requests/new.html` 접수폼:
   - 사업소 select(OFFICE_A/B/C 또는 화면 표시명)
   - pickup_date, 장소 유형, 주소, 품목 3개 수량
   - 모든 input 명시 label
   - 접수 버튼
   - Vanilla JS fetch로 POST `/api/requests`
   - 201 성공·422 오류를 live-status에 텍스트로 표시
4. `app/static/css/app.css`:
   - Wanted Primary `#0066FF` 또는 CSS token 사용
   - Pretendard token 사용
   - 20px page margin, 4px rhythm, 12px field radius, inset ring
   - 모바일 375px에서 1열·가로 스크롤 없음
   - 버튼/입력 hit area 44px 이상
5. `app/static/js/app.js`에 최소 제출 처리만 작성한다.

## 테스트

`tests/test_ui_form.py` 신규:
- GET `/requests/new` 200
- HTML에 label, 사업소, 날짜, 장소, 주소, 수량 필드가 있음
- `role="status"`, `aria-live="polite"` 존재
- `/static/css/wanted.css` 링크와 Primary token 사용 확인
- 기존 API 회귀

## 검증

```
uv run pytest tests/test_ui_form.py -v
uv run pytest tests/ -q
```

완료 보고는 실제 파일 목록과 테스트 결과를 포함하라. 목록·상세 화면은 이번 청크에서 구현하지 마라.
