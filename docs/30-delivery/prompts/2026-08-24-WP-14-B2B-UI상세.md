# WP-14-B2B 지시서 — Wanted 기반 상세 화면

담당: `local-builder`
수정 허용 경로: `app/server.py`, `app/templates/requests/detail.html`, `app/templates/requests/notfound.html`, `app/static/css/app.css`, `app/static/js/app.js`, `tests/test_ui_detail.py`

## 범위

접수 상세 화면 하나만 구현한다. 통계 화면·대시보드·새 API는 이번 작업에서 만들지 마라.

## 경로

```text
GET /admin/requests/{id}
```

## 필수 화면

- 접수번호
- 사업소명
- 수거 희망일
- 수거 장소 유형·주소
- 전동침대·휠체어·기타 소형 수량·전체 수량
- 현재 상태: 텍스트 + Wanted badge
- 생성/수정 시각
- 완료일
- 상태 이력: sequence·상태 텍스트·changed_at
- 다음 상태 변경 버튼: 현재 상태의 바로 다음 상태만 표시
- `DISINFECTED`/`DELIVERED`에서만 PDF 다운로드 버튼 표시
- `RECEIVED`에서만 수정 링크 표시
- 목록으로 돌아가기
- `role="status"`, `aria-live="polite"`
- 미존재 id는 404 템플릿으로 안전하게 표시

## 구현 규칙

- `app/server.py`의 FastAPI Request와 SQLAlchemy Request를 반드시 alias로 구분한다:
  `Request` / `Request as RequestModel`
- 기존 `/api/**`, `/requests/new`, `/admin/requests`를 깨뜨리지 마라.
- 기존 service의 `get_request`와 SQLAlchemy 이력 조회를 사용한다.
- 상태 변경/PDF/수정은 기존 API 링크를 호출한다.
- React/_ds_bundle.js/CDN을 사용하지 않는다.
- Wanted 토큰·기존 `app.css`를 사용한다.

## 테스트

`tests/test_ui_detail.py` 신규 작성:
1. 상세 GET 200 + 필수 정보와 상태 이력
2. RECEIVED 상세에서 수정 링크와 PICKED_UP 상태 버튼 존재
3. DISINFECTED 상세에서 PDF 버튼 존재
4. DELIVERED 상세에서 완료일과 PDF 버튼 존재
5. 미존재 상세 404 + 안전한 메시지
6. role=status·aria-live
7. 기존 API와 목록/접수폼 회귀

임시 SQLite + dependency override를 사용하라. 기존 테스트 파일은 수정하지 마라.

```
uv run python -c "import app.server; print('import ok')"
uv run pytest tests/test_ui_detail.py -v
uv run pytest tests/ -q
```

실제 템플릿·테스트를 작성하고 실행한 뒤 완료 보고하라.
