## 반드시 SQLAlchemy/Alembic/SQLite 관점에서 재검토해야 할 사항

1. **접수번호 생성**: 기존 설계는 H2 DB 시퀀스(`R-{10자리}`) 기반이었다. SQLite는 시퀀스를 지원하지 않는다. 대안을 제시하라 (예: 별도 카운터 테이블 + 트랜잭션 내 원자적 증가, 또는 다른 방식). 후보를 비교하고 권고안 하나를 제시하라.
2. **낙관적 잠금**: JPA `@Version` → SQLAlchemy `version_id_col` + `version_id_generator` 방식으로 재설계. 충돌 시 발생하는 예외(`StaleDataError`)와 처리 방식을 명시하라.
3. **시간 저장**: `Instant` → Python timezone-aware `datetime`(UTC 저장, KST 표시)으로 재설계.
4. **Enum**: JPA `EnumType.STRING` → SQLAlchemy `Enum` 또는 문자열 컬럼 + Python `Enum` 클래스로 재설계.
5. **마이그레이션**: Flyway SQL(V1~V3) → Alembic 버전 스크립트(revision 체인)로 1:1 대응 재설계. 초기 사업소 데이터 시딩 방법도 포함.
6. **테이블/컬럼/제약조건/인덱스**: 기존 설계와 동일하게 유지 (business_offices, requests, request_status_history 3개 테이블, CHECK 제약, UNIQUE, 인덱스 목록).
