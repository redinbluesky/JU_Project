## 검증 작업

### 1. 자동화 검증

다음 명령을 실제 실행하라:
```
uv run pytest tests/ -v
```

결과는 테스트 수, 실패 수, 경고 수를 정확히 기록하라.

### 2. 핵심 불변조건 독립 확인

코드와 테스트를 읽고 다음을 각각 판정하라:
- RECEIVED→PICKED_UP→DISINFECTED→DELIVERED 순차 전이
- 건너뛰기·역방향·중복·배송완료 이후 변경 거부
- 실패 요청의 상태·이력·카운터 부분 저장 방지
- StaleDataError 409 처리 및 자동 재시도 없음
- PDF 소독완료 이전 거부, 이후 허용, 프로토타입 표시
- 목록·통계·엑셀 공통 pickup_date/사업소/상태 필터
- XLSX 10개 열·DB 정합성·수식 인젝션 방지
- SQLite 재오픈 후 데이터·이력 보존
- 로그/문서/테스트에 실제 개인정보·자격증명 미사용

### 3. QA-001~048 판정

각 항목에 다음을 기록하라:
- 판정: 통과 / 조건부 / 미검증 / 실패
- 실제 증거: 테스트 파일·명령·코드 경로
- 남은 위험 또는 차단 사유

QA-001~040 중 API/화면 기능이 실제로 구현되지 않은 항목은 통과로 위장하지 말고 `미검증` 또는 `조건부`로 판정하라. 특히 UI(PC Chrome/모바일, 레이블, aria-live, 색상 외 상태 표현)가 코드 범위에 없으면 미검증으로 남겨라.

### 4. 출시 판정

최종 판정은 다음 중 하나만 선택하라:
- 출시 가능
- 조건부 가능
- 출시 불가

현재 기술 프로토타입 범위에서 실제로 검증된 것과 아직 검증되지 않은 것을 분리하라. 과도하게 낙관적인 판정은 금지한다.
