# WP-14-B 지시서 — Jinja UI 1차: 접수폼·목록·상세 화면

담당: `local-builder` | 수정 허용 경로: `app/server.py`, `app/templates/`, `app/static/`, `tests/test_ui_pages.py`

## 배경

quality-gate가 WP-13에서 UI 미구현을 조건부 출시 조건으로 판정했다. UX 명세(`docs/20-design/UX-화면-명세.md`) 기준으로 화면을 구현한다.

## 이번 범위

이번 청크는 접수폼·목록·상세 화면과 공통 레이아웃만 구현한다. 대시보드와 모바일 세부 최적화는 다음 청크에서 보완한다.

### 화면 경로

- `GET /requests/new` — 접수폼
- `GET /admin/requests` — 목록 + 기간/사업소/상태 필터
- `GET /admin/requests/{id}` — 상세

### 필수 화면 요소

접수폼:
- 사업소 선택
- 수거 희망일
- 장소 유형
- 주소
- 전동침대/휠체어/기타 수량
- 접수 생성 버튼
- 명시적 `<label>`
- 오류/성공 메시지 영역: `role="status"`, `aria-live="polite"`

목록:
- 기간·사업소·상태 필터
- 접수번호·사업소·수거희망일·상태·전체수량 테이블
- 상세 링크
- 엑셀 다운로드 링크
- 상태는 색상만이 아니라 텍스트로 표시

상세:
- 전체 필수 정보
- 현재 상태 텍스트
- 상태 변경 버튼
- PDF 다운로드 버튼은 DISINFECTED/DELIVERED에서만 활성화
- 메시지 영역에 role/aria-live 적용

### 구현 규칙

- Jinja2Templates와 Vanilla JS/fetch 사용
- API 검증을 우회하지 말고 기존 API를 호출
- 기존 `/api/**` 경로와 기존 테스트를 깨뜨리지 마라
- 개인정보·자격증명·실제 운영 데이터 사용 금지
- UX 명세의 승인 디자인 토큰이 있으면 사용하라
