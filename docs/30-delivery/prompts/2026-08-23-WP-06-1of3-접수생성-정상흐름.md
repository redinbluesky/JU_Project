## 작업 (이번 청크는 "정상 흐름"만, 오류 검증은 2/3에서)

### 1. Pydantic 스키마 (`app/main/schemas/request.py`)
- `RequestCreate`: business_office_id, pickup_date, pickup_location_type, pickup_address, electric_bed_quantity, wheelchair_quantity, other_small_quantity
- `RequestOut`: id, request_no, business_office_id, pickup_date, pickup_location_type, pickup_address, current_status, 수량 3개, completion_date, created_at, updated_at

### 2. 서비스 함수 (`app/main/services/request_service.py`)
- `create_request(db: Session, data: RequestCreate) -> Request`
  - 접수번호는 이번 청크에서 임시로 `f"R-{db.query(Request).count()+1:010d}"` 같은 단순 방식으로 채번 (3/3에서 RequestNoCounter로 교체 예정 — 지금은 API 골격과 정상 흐름만 완성)
  - 최초 상태 `RECEIVED`, `created_at`/`updated_at` 현재 UTC 시각
  - 저장 직후 `RequestStatusHistory`에 sequence=1, status=RECEIVED 이력 1건도 같은 트랜잭션에서 함께 생성 (데이터-모델 8절 "상태·이력 동일 트랜잭션" 원칙)

### 3. API 라우터 (`app/main/api/requests.py`)
- `POST /api/requests` — RequestCreate 받아서 RequestOut 반환, status_code=201
- `app/server.py`에 라우터 등록 (`app.include_router`)

### 4. pytest (`tests/test_request_create.py`) — 필수, 이번 청크 완료 조건
httpx.AsyncClient 또는 TestClient로 실제 API 호출 검증. 최소 3개 테스트:
- `test_create_request_success`: 정상 입력 → 201, request_no 부여됨, current_status='RECEIVED' 확인
- `test_create_request_persists_to_db`: 생성 후 DB에서 직접 조회해 1건 존재, created_at 기록 확인
- `test_create_request_creates_history`: 생성 후 RequestStatusHistory에 sequence=1, status=RECEIVED 이력 1건 존재 확인

테스트는 실제 DB 파일을 오염시키지 않도록 임시 SQLite(`sqlite:///:memory:` 또는 임시 파일)를 사용하는 fixture로 작성하라. `runtime/db/ju-project.db`를 직접 건드리지 마라.
