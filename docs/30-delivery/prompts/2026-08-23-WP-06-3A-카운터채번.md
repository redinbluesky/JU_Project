# WP-06 실행 지시서 (3/3-A) — RequestNoCounter 채번만 구현

담당: `local-builder` | 수정 허용 경로: `app/main/services/request_service.py`, `tests/test_request_counter.py`

## 이번 작업은 카운터 채번 하나만 한다

수정 API, RequestUpdate 스키마, 기타 파일은 이번 작업에서 건드리지 마라.

## 구현

`app/main/services/request_service.py`의 임시 `count()+1` 채번을 제거하고, 데이터-모델 3.3절 방식으로 교체하라.

```python
result = db.execute(text(
    "UPDATE request_no_counter "
    "SET current_value = current_value + 1 "
    "WHERE id = 1 RETURNING current_value"
))
next_value = result.scalar_one()
request_no = f"R-{next_value:010d}"
```

- 카운터 증가, Request INSERT, 최초 History INSERT는 기존처럼 하나의 `db.commit()` 트랜잭션 안에 있어야 한다.
- SQLite RETURNING이 실패하는 환경이면 UPDATE 후 SELECT 폴백을 추가하라.
- 기존 서비스의 나머지 로직은 유지하라.

## 테스트

`tests/test_request_counter.py`를 작성하라. 기존 테스트 fixture 패턴을 참고하되 임시 SQLite를 사용하라.
1. 3건 생성 → R-0000000001, R-0000000002, R-0000000003
2. 생성 후 request_no_counter.current_value == 3
3. 생성 실패 시 카운터 롤백 확인. 가장 간단한 방법은 service 내부에서 commit 전 예외가 나도록 잘못된 데이터로 호출한 뒤 rollback하고, 다음 정상 생성 번호가 R-0000000001인지 확인하는 것이다.
