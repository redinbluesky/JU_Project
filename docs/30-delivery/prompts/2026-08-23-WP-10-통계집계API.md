## API

```text
GET /api/statistics
```

목록 API와 동일한 필터를 사용한다:
- `pickup_date_from`
- `pickup_date_to`
- `business_office_id`
- `current_status`

필터 규칙:
- 기간 기준은 반드시 `pickup_date`
- 조건은 AND 결합
- from > to는 422
- 목록 API와 동일한 대상 행 집합을 사용

응답은 최소한 다음 구조를 제공하라:

```json
{
  "total_requests": 0,
  "by_business_office": {"1": 0},
  "by_status": {"RECEIVED": 0, "PICKED_UP": 0, "DISINFECTED": 0, "DELIVERED": 0},
  "quantities": {
    "electric_bed": 0,
    "wheelchair": 0,
    "other_small": 0,
    "total": 0
  }
}
```

- 0건이어도 네 상태 키와 수량 키를 빠뜨리지 마라.
- 사업소별 집계는 필터 결과에 실제로 존재하는 사업소만 포함해도 된다.
- 가능하면 목록 API와 동일한 service query/helper를 재사용하라. 별도의 원본 데이터나 임의 집계를 만들지 마라.

## pytest 필수

`tests/test_statistics.py` 신규 작성. 임시 SQLite + StaticPool로 사업소 2개, 서로 다른 pickup_date와 상태를 가진 접수 4건을 준비하라.

최소 테스트:
1. 전체 접수 건수
2. 사업소별 집계
3. 상태별 집계
4. 전체·품목별 수량 및 합계
5. pickup_date 기간 필터 집계
6. 사업소 필터 집계
7. 상태+기간 복합 필터 집계
8. from > to 422
9. 0건 필터 결과도 응답 구조 유지
10. 목록 API의 동일 필터 결과와 통계 total 일치

각 테스트는 API 결과를 직접 SQLAlchemy로 계산한 기대값과 대조하라.

기존 API·PDF·조회 테스트 파일은 수정하지 마라.
