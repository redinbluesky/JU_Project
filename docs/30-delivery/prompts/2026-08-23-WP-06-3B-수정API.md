# WP-06 실행 지시서 (3/3-B) — 접수 수정 API만 구현

담당: `local-builder` | 수정 허용 경로: `app/main/schemas/request.py`, `app/main/services/request_service.py`, `app/main/api/requests.py`, `tests/test_request_update.py`

## 작업 범위 제한

이번 작업은 **수정 API만** 구현한다. 접수번호 채번은 이미 완료되어 있으므로 건드리지 마라. `tests/test_request_counter.py`와 기존 테스트도 건드리지 마라.

## 구현

1. `app/main/schemas/request.py`에 `RequestUpdate` 추가:
   - pickup_date: date
   - pickup_location_type: PickupLocationType
   - pickup_address: 1~255자 문자열
   - electric_bed_quantity, wheelchair_quantity, other_small_quantity: 0 이상 정수
   - `RequestCreate`와 동일한 날짜 검증(오늘 날짜 포함 거부), 전체 수량 합계 1 이상 검증
   - business_office_id는 포함하지 않는다(수정 불가)

2. `app/main/services/request_service.py`에 `update_request(db, request_id, data)` 추가:
   - Request를 못 찾으면 ValueError
   - current_status가 RECEIVED가 아니면 ValueError
   - 위 필드만 변경하고 updated_at 갱신
   - 성공 시 commit, 반환

3. `app/main/api/requests.py`에 `PATCH /api/requests/{request_id}` 추가:
   - 성공 200 + RequestOut
   - ValueError는 409
   - 나머지 예외는 rollback 후 500

## 테스트

`tests/test_request_update.py`만 새로 작성하라. 기존 테스트 파일은 수정하지 마라.
- RECEIVED 접수 PATCH 성공(200)
- 수정한 모든 필드가 DB에 저장됨
- business_office_id는 수정되지 않음
- PICKED_UP 상태로 직접 바꾼 접수 PATCH는 409
- 존재하지 않는 id는 409
- 날짜/수량 검증 실패는 API 422

임시 SQLite fixture에서 RequestNoCounter(id=1,current_value=0)도 시딩하라.
