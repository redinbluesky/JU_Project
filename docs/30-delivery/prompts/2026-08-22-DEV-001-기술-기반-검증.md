## 1. 목적

기능 개발 전에 승인된 Java 단일 애플리케이션 기술 스택이 현재 Windows 로컬 환경에서 실제로 빌드·기동되고, H2 파일 보존·Flyway·PDF·XLSX 생성까지 동작하는지 검증한다.

이 작업은 기술 기반 검증이다. 접수폼, 관리자 화면, 상태 전이 서비스, 통계, 실제 PDF 엔드포인트와 엑셀 다운로드 엔드포인트를 구현하지 않는다.

## 2. 수정 허용 경로

```text
app/**
runtime/db/**       실행 생성물만
runtime/pdf/**      실행 생성물만
runtime/xlsx/**     실행 생성물만
```

다음은 수정하지 않는다.

```text
.hermes.md
.gitignore
docs/**
README.md
```

추가 경로가 필요하면 작업을 중지하고 선점 확장을 요청한다.

## 3. 승인 스택

- OpenJDK 21
- Spring Boot 4.0.x 유지보수 패치: 작업 시작 시 공식 최신 패치를 확인하고 정확한 버전을 보고한 뒤 고정
- Maven Wrapper
- Spring MVC, Thymeleaf, Vanilla JS 기반 의존성
- Jakarta Bean Validation
- Spring Data JPA
- H2 2.4.x 파일 모드
- Flyway
- Apache PDFBox 3.0.7 후보
- Apache POI 5.5.1 후보
- JUnit 5, Spring Boot Test, MockMvc

승인 없이 다른 프레임워크·DB·PDF·엑셀 라이브러리로 변경하지 않는다.

## 4. 구현 범위

### 4.1 최소 프로젝트

- `app/`에 Maven Wrapper 기반 Spring Boot 프로젝트를 구성한다.
- Java 21을 컴파일 기준으로 사용한다.
- 단일 실행 JAR 구조를 사용한다.
- 애플리케이션 컨텍스트가 기동되는 최소 메인 클래스를 둔다.
- 운영용 인증·외부 API·SPA·Docker를 추가하지 않는다.

### 4.2 의존성 검증

- Spring Boot BOM이 관리하는 Thymeleaf, JPA, H2, Flyway, Validation, 테스트 의존성을 확인한다.
- PDFBox와 POI의 직접 고정 버전을 명시한다.
- Maven dependency tree를 실행해 버전 충돌과 중복 주요 버전을 확인한다.
- 취약하거나 호환되지 않는 의존성이 확인되면 기능 구현을 진행하지 않고 보고한다.

### 4.3 Flyway·H2 파일 보존

- 승인된 데이터 모델의 V1~V3 마이그레이션 골격을 작성한다.
  - V1: `business_offices` 및 가상 사업소 A/B/C
  - V2: `requests` 및 `request_no_seq`
  - V3: `request_status_history`
- `TIMESTAMP WITH TIME ZONE`, 고정 상태 CHECK, 품목 수량 CHECK, 합계 CHECK, FK, UNIQUE와 인덱스를 데이터 모델과 일치시킨다.
- H2 URL은 `jdbc:h2:file:runtime/db/ju-project` 방향을 사용한다.
- `create-drop`과 인메모리 DB를 사용하지 않는다.
- Flyway 적용 후 애플리케이션을 종료·재실행해 가상 사업소 sentinel 데이터와 schema history가 유지되고 V1이 재실행되지 않는지 실제 확인한다.

### 4.4 PDF 최소 검증

- PDFBox로 최소 한 페이지의 유효한 PDF를 생성하는 자동화 테스트를 작성한다.
- `기술 프로토타입 — 공단 제출용 아님` 표시를 포함한다.
- 생성물을 `runtime/pdf/`에 두고 실제로 열거나 PDFBox로 다시 로드해 유효성을 확인한다.
- 접수 데이터 삽입과 다운로드 엔드포인트는 구현하지 않는다.

### 4.5 XLSX 최소 검증

- Apache POI로 필수 헤더 10개가 있는 유효한 `.xlsx`를 생성하는 자동화 테스트를 작성한다.
- 데이터 행 0개의 빈 결과 파일을 생성하고 다시 열어 헤더 수와 행 수를 확인한다.
- `=`, `+`, `-`, `@`로 시작하는 문자열이 수식이 아닌 텍스트 셀인지 확인하는 테스트를 작성한다.
- 생성물을 `runtime/xlsx/`에 둔다.
- 실제 목록 조회나 다운로드 엔드포인트는 구현하지 않는다.

## 5. 필수 테스트

1. Spring 애플리케이션 컨텍스트 기동
2. Flyway V1~V3 적용
3. H2 파일 생성
4. 종료·재실행 후 사업소 데이터 보존
5. 재실행 후 사업소 중복 없음
6. `request_no_seq` 존재와 NEXT VALUE 획득
7. PDF 생성·재로드
8. XLSX 생성·재로드
9. 빈 XLSX 헤더 10개·데이터 0행
10. 수식 주입 문자열의 텍스트 셀 처리

## 6. 실행·검증 명령

Windows에서 실제 동작하는 명령을 사용한다. 최소한 다음을 실행하고 사용한 정확한 명령을 보고한다.

```text
Maven Wrapper 버전 확인
clean test
dependency:tree
package
생성 JAR 기동 및 종료
재기동 후 H2 데이터 확인
```

예상 명령을 성공 증거로 쓰지 않는다. 명령의 종료 코드와 테스트 수를 실제 결과로 보고한다.

## 7. 완료 기준

- Maven Wrapper가 전역 Maven 없이 실행된다.
- 승인된 Spring Boot 4.0.x 버전으로 컴파일·테스트·패키징된다.
- 애플리케이션이 실제 기동된다.
- 의존성 트리에 차단 충돌이 없다.
- H2 파일 DB와 Flyway V1~V3가 동작한다.
- 종료·재실행 후 데이터와 schema history가 유지된다.
- PDF와 XLSX 생성·재검증 테스트가 통과한다.
- 실제 개인정보·외부 API·비밀정보가 코드·로그·문서에 없다.
- 접수·상태 전이 등 승인되지 않은 기능 구현이 없다.

하나라도 실패하면 DEV-001은 완료가 아니라 `중단` 또는 `조건부 실패`로 보고한다.
