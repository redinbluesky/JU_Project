# WP-07 실행 지시서 (A) — 상태 전이 도메인 서비스 + 정상/불법 전이 pytest

담당: `local-builder` | 수정 허용 경로: `app/main/services/request_service.py`, `tests/test_status_transition.py`

## 이번 청크 범위

이번에는 API 라우터를 추가하지 말고, **서비스 함수와 테스트만** 작성하라. WP-06의 접수 생성·카운터 채번·수정 API는 건드리지 마라.

## 승인된 상태 전이

```text
RECEIVED → PICKED_UP → DISINFECTED → DELIVERED
```

시스템 설계 7.3절의 규칙:
- 바로 다음 상태만 허용
- 건너뛰기·역방향·동일 상태 중복·DELIVERED 이후 전부 거부
- 현재 상태 변경과 이력 추가는 같은 트랜잭션
- 이번 A 청크에서는 API와 StaleDataError 처리는 구현하지 않는다

## 구현

`app/main/services/request_service.py`에 다음 함수를 추가하라.

```python
def transition_request_status(db: Session, request_id: int, target_status: RequestStatus) -> Request:
    ...
```

요구사항:
1. 존재하지 않는 Request는 ValueError
2. 허용 전이 맵을 명시적으로 둔다
3. target_status가 현재 상태의 바로 다음 상태가 아니면 ValueError
4. 다음 sequence를 현재 이력 최대값 + 1로 계산
5. RequestStatusHistory를 추가하고 current_status를 변경
6. `DELIVERED`이면 completion_date를 현재 UTC 날짜로 기록
7. updated_at 갱신
8. 하나의 `db.commit()`으로 처리
9. 실패 시 상태나 이력이 변경되지 않도록 commit 전에 검증을 끝낸다

## pytest 필수

`tests/test_status_transition.py` 신규 작성. 임시 SQLite + StaticPool 또는 기존 fixture 패턴을 사용하고 RequestNoCounter도 시딩하라.

반드시 포함할 테스트:
- RECEIVED → PICKED_UP 성공, 현재 상태·이력 sequence=2 확인
- PICKED_UP → DISINFECTED 성공, sequence=3 확인
- DISINFECTED → DELIVERED 성공, sequence=4·completion_date 기록 확인
- RECEIVED → DISINFECTED 건너뛰기 거부 + 상태/이력 불변
- PICKED_UP → RECEIVED 역방향 거부 + 상태/이력 불변
- RECEIVED → RECEIVED 중복 거부
- DELIVERED → DISINFECTED 거부
- 존재하지 않는 id 거부
