# WP-12 실행 지시서 (B) — PDF/XLSX/통계 정합성 + SQLite 재오픈 보존

담당: `local-builder` | 수정 허용 경로: `tests/test_integration_artifacts.py`, `app/**`(결함 발견 시에만)

## 배경

WP-12-A 핵심 업무 흐름이 완료됐고 전체 회귀 117개가 통과했다. 이번 청크는 나머지 통합검증만 수행한다. 기존 기능을 새로 만들지 말고 실제 API를 연결해 검증하라.

## 검증 범위

임시 SQLite 파일 DB와 TestClient를 사용하라.

1. 접수를 생성하고 상태를 `DISINFECTED`까지 전이
2. PDF 다운로드 200, `application/pdf`, `%PDF` 헤더, 크기>0, 프로토타입 표시 확인
3. 통계 API와 목록 API의 동일 필터 `total` 일치 확인
4. 동일 필터로 XLSX 다운로드 후 openpyxl 재로드
   - 필수 10개 헤더
   - 행 수 = 목록 결과
   - 주요 DB 원본 값 대조
   - formula data_type='f' 셀 0개
5. `DELIVERED`까지 전이하고 completion_date 확인
6. 같은 SQLite 파일에 대해 세션/엔진을 닫고 새 engine/session으로 재오픈
   - Request 1건 존재
   - current_status=DELIVERED
   - history 4건, sequence [1,2,3,4]
   - completion_date 보존

## 테스트

`tests/test_integration_artifacts.py` 신규 작성. 기존 테스트 파일은 수정하지 마라. PDF/XLSX는 tmp_path 출력 주입으로 runtime 폴더를 오염시키지 않도록 하라. 재오픈 검증은 실제 임시 `.db` 파일을 사용하라.

최소 4개 테스트:
- PDF 통합 검증
- 통계·목록 정합성
- XLSX·DB 정합성 및 수식 셀 0
- SQLite 파일 재오픈 보존

```
uv run pytest tests/test_integration_artifacts.py -v
uv run pytest tests/ -q
```
